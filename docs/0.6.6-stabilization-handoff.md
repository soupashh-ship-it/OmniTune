## Major Stabilization Work Completed

### Release and Repository Hygiene

- Release signing no longer falls back to debug signing.
- Release signing uses environment variables and GitHub repository secrets.
- GitHub tag workflow builds signed release APKs and uploads the APK plus SHA-256 file.
- Firebase is opt-in and local/open-source builds work without `google-services.json`.
- `.gitignore` blocks keystores, signing files, APK/AAB outputs, idsig files, zips, crash logs, and local properties.
- Keystore, Google services files, APKs, idsig files, zips, and crash logs are not tracked.
- CI/build workflow uses JDK 21.

### Playback Stability

- Stream client fallback was hardened so all configured player clients can be attempted.
- Stream resolve failures now have better typed/error-aware handling internally.
- Queue resolution paths were improved so playback, Play Next, Add to Queue, restored queues, and radio insertion use safer stream resolution.
- Force-stop/process-death recovery was fixed so reopening the app and playing a new search result does not reuse stale direct stream URLs.
- Stream cache is cleared on service startup and playback errors invalidate stale stream URLs.
- Failed playback is surfaced instead of silently disappearing.

### Queue and Player State

- Queue, Add to Queue, and Play Next were verified in prior QA.
- Current queue order and selected item behavior were preserved.
- MiniPlayer active state was fixed and verified against playback metadata.
- Full player and MiniPlayer now stay aligned with the same player state.

### Search Stability

- Search error states were improved.
- Network-disabled search now shows clear offline copy instead of blank or endless loading states.
- Search can show cached results when available.
- Search list performance was improved with safer list keys/content handling and bounded artwork loading.

### Downloads and Offline Playback

- Download/offline path was partially hardened around Media3 cache/download state.
- Completed downloads are distinguished from non-downloaded online media.
- Completed download rows show clearer status copy: `Downloaded song is ready offline.`
- Offline downloaded playback was verified in the 0.6.5/0.6.6 baseline, but should still be regression-tested after installing each public release asset.

### Settings and Update System

- Added manual in-app update checking from the official GitHub latest release endpoint.
- Update checker parses GitHub release metadata and selects signed release APK assets.
- Update flow verifies package name and version code before launching Android's installer.
- APK install uses FileProvider/content URI and does not attempt silent install.
- Added safe install-permission handling for Android's unknown-app-source flow.
- Settings crash from framework drawable usage in Compose was fixed.

### Diagnostics

- Added sanitized diagnostic export from Settings.
- Diagnostic export excludes secrets, cookies, auth tokens, PoToken, visitor data, Last.fm sessions, Firebase identifiers, passwords, and keystore data.

### Network-Disabled UX

- Network checks now require usable internet capability.
- Offline search copy includes:
  - `No internet connection.`
  - `Retry when online.`
- Non-downloaded playback while offline surfaces:
  - `This song is not downloaded and cannot play offline.`
- Generic offline playback source errors surface:
  - `No internet connection. Retry when online.`

### Media Notification and Lock-Screen Compatibility

- Playback notification is bound to OmniTune's explicit `music_player` channel and stable notification ID.
- Playback channel is low importance, public on lock screen, no badge, no sound, and no vibration.
- Notification small icon is now an app-owned vector icon.
- Added a guarded platform `Notification.MediaStyle` fallback for OEMs where Media3 exposes the MediaSession but the notification is not posted as a visible media notification.
- Fallback uses the same channel and notification ID, so it updates the playback notification instead of creating a duplicate.
- Notification actions include Previous, Play/Pause, and Next.
- Added debug-only `MediaControls` logs for notification permission, channel importance, session state, player state, current title, mediaId, and queue count.
- Added Settings > Advanced > Fix notification & lock-screen controls.
- Added shortcuts to app notification settings, app details, and battery optimization settings.
- Added Vivo/iQOO/Funtouch OS guidance for notifications, lock-screen notifications, background activity, unrestricted battery, autostart, and cleanup exclusions.

## Release Discipline

- Do not commit APKs, AABs, idsig files, zips, keystores, signing properties, `google-services.json`, crash logs, or local secrets.
- Use version tags such as `v0.6.7` to trigger signed release builds.
- Release assets must use:
  - `OmniTune-vX.Y.Z-release.apk`
  - `OmniTune-vX.Y.Z-release.apk.sha256`
- Signed public releases should be built by GitHub Actions so the same release key is used.
