# v0.8.0 Audio Quality Settings QA

**Branch**: `feature/v0.8.0-audio-quality-settings`

**PlaybackQualityMode implementation**:
- Fully mapped `PlaybackQualityMode` with values: `AUTO`, `DATA_SAVER`, `BALANCED`, and `HIGH`.
- Avoided fake `LOSSLESS` or `HI_RES` labels since YouTube streams are universally compressed Opus/AAC.

**Settings UI status**:
- Implemented `EnumPreferenceRow` in `SettingsScreen.kt` under "Audio quality" labelled "Stream quality".
- Mode descriptions provide honest explanations without misleading claims.
- Warning block displayed: "Changes apply from the next song."

**Persistence status**:
- Implemented and wired natively into `dataStore` through `PlaybackQualityModeKey`.
- Default value is safely typed to `PlaybackQualityMode.AUTO`.
- Fully persists across app restarts without breaking state loading.

**Resolver integration status**:
- Wired to `StreamUrlResolver.kt`. 
- `mapQuality` converts `PlaybackQualityMode` accurately to `StreamQuality` ranges supported by `StreamExtractor`.
- Background `MusicService` coroutines dynamically fetch the user's quality preference via `this.dataStore.data.first()` safely per queue insertion or playback start.

**Does this actually change stream quality?**:
Yes. The resolver translates `DATA_SAVER` to low bitrate, `BALANCED` to mid bitrate, and `HIGH` to the highest available compressed opus stream from the internal extractor.
