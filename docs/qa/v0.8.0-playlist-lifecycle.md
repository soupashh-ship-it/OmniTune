# v0.8.0 Playlist Lifecycle QA

## Implemented Behavior
- **Rename playlist**: Added rename functionality in `PlaylistDetailScreen` header options (3-dots menu). Validates that the new name is not blank.
- **Delete playlist**: Added delete functionality in `PlaylistDetailScreen`. A confirmation dialog warns that "Songs and downloads will not be deleted". Deletion safely drops the playlist and its `playlist_song_map` entries (via cascade/query) without destroying `song` entities, liked status, or downloads.
- **Remove track**: A "Remove from this playlist" action was added to the unified `TrackOptionsBottomSheet`. Removing a track only deletes its link in `playlist_song_map`.
- **Global add track**: All song rows use `TrackMenuProvider` to surface the "Add to playlist" button.

## Protected Playlist Rules
- The UI options to Rename or Delete a playlist only appear if `playlist.isEditable == true`.
- Built-in/virtual playlists like **Liked Songs** or **Downloads** are not technically `PlaylistEntity` driven on those screens (they have their own specific views), but if they were to load as playlists, their `isEditable` flag is false, disabling destructive actions.
- Items removed from Liked Songs use the existing "Unlike" toggle.

## Duplicate Prevention Behavior
- In `DatabaseDao.addSongToPlaylist`, a query `checkInPlaylist(playlist.id, songId)` is run before insertion.
- If the count is > 0, the insertion is skipped.
- The `LibraryViewModel` function `addToPlaylist` was made `suspend` and now returns a `Boolean` representing whether an insertion actually occurred. 
- The `TrackMenuProvider` catches this result and toasts either "Added to playlist" or "Already in playlist".
- **Note**: Current duplicate prevention is application-level, not database-enforced (no unique composite index in schema).

## Tests Added
In `MusicDatabaseTest.kt` (Android instrumented test):
- `addSameSongTwiceDoesNotDuplicate`: Validates duplicate prevention at the DAO level.
- `deletePlaylistRemovesCrossrefsButNotSongs`: Confirms that `database.delete(playlist)` destroys cross-references but keeps `SongEntity`.
- `removeTrackRemovesOnlyCrossref`: Validates `database.removeSongFromPlaylist()` works without deleting `SongEntity`.

## Known Limitations
- Ordering tracks via drag-and-drop within a playlist is not yet implemented.
- Playlists are strictly local and do not sync bidirectional to YouTube Music.
